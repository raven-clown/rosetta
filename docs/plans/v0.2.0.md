# v0.2.0 Implementation Plan

**Goal:** rosetta keeps its state in SQL and can be run from an admin API. Runs and sessions are stored in SQLite or Postgres, agents and API keys can be created at runtime, every write leaves an audit record, and agents report reasoning tokens and transponder's limit errors properly.

**Spec:** `docs/design.md` sections 9 to 13, `mothership/CONTRACT.md` and `mothership/docs/scale.md`.

**Tracking issue:** #49. Each task below has its own issue, a sub-issue of #49, on the v0.2.0 milestone.

**Tech stack:** Go 1.26, `modernc.org/sqlite`, `github.com/jackc/pgx/v5/stdlib`, `go.yaml.in/yaml/v3`, `github.com/santhosh-tekuri/jsonschema/v6` (tests only, already in the module graph), standard library otherwise.

## Moved to v0.3.0

- Limits from the shared profiles (`agent.runs` rate, concurrency, `max_steps`, `timeout`, and `requests`), `RateLimit` headers, `rosetta_limited_total`.
- CloudEvents usage events (`dev.mothership.rosetta.run.finished.v1`) with an outbox, and `rosetta_events_dropped_total`.
- Admin API: `GET /config`, `PATCH /settings`, upstream secrets encrypted with `storage.secret_key`, `GET /tools`, `GET /agents/{name}/endpoints`, `GET /usage`.
- A2A tasks in SQL (`a2a_tasks` behind a2a-go's task store), so A2A tasks survive a restart and work across replicas.
- A batch writer for run records, OIDC, OTLP traces, `roles`.
- Deleting a stored agent that a config agent of the same name shadows, and caching upstream checks for `GET /admin/v1/status`.

Each gets an issue on the v0.3.0 milestone when this plan ships. An operator allowlist for the URLs of `a2a` agents made through the admin API goes there too; until then only `admin` keys may create them.

## Decisions made here

1. **The in-memory store is SQLite in memory.** `store.Open(ctx, "sqlite://:memory:")` gives the same code as the file store, so there is one implementation of each query and the shared suite covers every store. Library users keep `session.Memory` as the default history store and never get a file.
2. **No config means SQLite and a bootstrap key.** `rosetta serve` with no `--config` opens `rosetta.db` in the working directory, turns auth on, prints a one-time admin key to stderr on first start (or takes `ROSETTA_BOOTSTRAP_ADMIN_KEY`), and still serves the `echo` agent so the quickstart works. This breaks v0.1's open demo, and the changelog says so.
3. **Keys from the database are cached.** Serving a request reads no SQL for auth. API keys are stored as SHA-256 hashes, loaded with the agents, and swapped in on each reload. The caller ID of a stored key is `key:<id>`.
4. **Reload by revision.** Every write to agents or keys bumps `revision` in the same transaction. Each process checks it every 2 seconds and rebuilds its agent list and key set. An admin write in the same process reloads at once.
5. **`If-Match` is checked when sent.** Absent means no check, a mismatch is 409 `version_conflict`, as in transponder. `GET` answers with `ETag: "<version>"`.
6. **Audit in the same transaction.** Each store write method takes the audit record and writes both, or neither.
7. **Run records are written after the run.** Synchronously, with their own short timeout, after the answer has gone out. A failure is logged and counted and does not change the run's result. A batch writer comes in v0.3.0.

## Global constraints

- Everything from milestones 1 and 2: table tests, `httptest` and pipes only, no `time.Sleep`, 80% total coverage, lint clean on golangci-lint v2.15, LF golden files, short comments about why, no em-dashes.
- Every table except `revision` and `schema_migrations` has `org_id TEXT NOT NULL DEFAULT 'default'` and every query filters by it.
- Migrations are embedded SQL, one folder per dialect, numbered from `0001`, additive only (expand and contract).
- Admin API: JSON under `/admin/v1/`, errors `{"error":{"code","message","field"}}`, lists `cursor` and `limit` (default 50, at most 500) answering `{"items":[...],"next_cursor":"..."}` with `next_cursor` absent on the last page, `version` on every resource, items from config or code read-only with `managed_by_file` or `managed_by_code`.
- Roles: `admin` everything, `member` agent and session writes, `viewer` reads. Only `admin` and `member` run agents. With `auth.disabled`, the admin API answers loopback callers only.
- Secrets are never returned. A new API key is shown once.

## Review focus

1. **Two writers, one row.** Two `PATCH` calls with the same `If-Match`: one wins, the other gets 409. Test in Task 6.
2. **Migrations on a newer database.** A database migrated by a newer binary stops startup with a message naming both versions. Replicas migrating at once on Postgres do not race (advisory lock). Tests in Task 3.
3. **Key revoked while cached.** A revoked key stops working within one reload, and at once in the process that revoked it. Test in Task 7.
4. **Config agent shadowed.** Creating an API agent named like a config or code agent is 409 `conflict` with `field: name`; config agents cannot be changed or deleted. Test in Task 6.
5. **Store down during a run.** History load or run record write fails: the run still answers, the error is logged and counted. Test in Task 4.

### Task 3: The SQL store and migrations (#52)

**Files:** Create `store/store.go`, `store/open.go`, `store/migrate.go`, `store/sessions.go`, `store/runs.go`, `store/agents.go`, `store/keys.go`, `store/audit.go`, `store/page.go`, `store/migrations/sqlite/0001_init.sql`, `store/migrations/postgres/0001_init.sql`, `store/storetest/storetest.go`. Test `store/store_test.go` (memory and SQLite file), `store/postgres_test.go` (`integration` tag, `ROSETTA_TEST_POSTGRES_DSN`).

**Interfaces:**
- `func Open(ctx context.Context, dsn string) (*Store, error)` for `sqlite://<path>`, `sqlite://:memory:`, `postgres://...` and `postgresql://...`. SQLite gets WAL, `busy_timeout=5000` and foreign keys; `:memory:` uses one connection. `Open` runs migrations unless `OpenOptions{NoMigrate: true}` is passed through `OpenWith`.
- `func (s *Store) Migrate(ctx context.Context) (applied int, err error)`. Postgres holds `pg_advisory_lock` for the run. `ErrTooNew` when the database has a migration this binary does not know, with both numbers in the message.
- `*Store` implements `session.Store` (History, Append, Delete by agent and session key), plus:
  - Sessions: `ListSessions(ctx, SessionFilter{Agent}, Page) ([]Session, string, error)`, `GetSession(ctx, id) (Session, []rosetta.Message, error)`, `DeleteSession(ctx, id string, version int64, a Audit) error`. A session has `ID`, `Agent`, `Caller`, `Messages` count, `Created`, `Updated`, `Expires`, `Version`. TTL and the message cap come from `Options` on the store.
  - Runs: `SaveRun(ctx, Run) error`, `ListRuns(ctx, RunFilter{Agent, Protocol, Status, From, To}, Page)`, `GetRun(ctx, id)`. A run has `ID`, `Agent`, `Protocol`, `SessionID`, `Caller`, `Status`, `Error`, `Started`, `Ended`, token counts and `RequestID`.
  - Agents: `ListAgents(ctx)`, `GetAgent(ctx, name)`, `CreateAgent(ctx, Agent, Audit)`, `UpdateAgent(ctx, Agent, version, Audit)`, `DeleteAgent(ctx, name, version, Audit)`. An agent has `Name`, `Spec json.RawMessage`, `Version`, `Created`, `Updated`, `UpdatedBy`.
  - Keys: `ListKeys(ctx)`, `CreateKey(ctx, Key, Audit)`, `RevokeKey(ctx, id, version, Audit)`, `CountKeys(ctx)`. A key has `ID`, `Name`, `Role`, `Prefix`, `Hash`, `Created`, `Revoked`, `Version`.
  - Audit: `ListAudit(ctx, AuditFilter{Action, Target, From, To}, Page)`. A record has `ID`, `Time`, `Actor`, `Action`, `Target`, `Details json.RawMessage`.
  - `Revision(ctx) (int64, error)`, `Prune(ctx, now time.Time, runsRetention time.Duration) (int64, error)`, `Dialect() string`, `Ping(ctx) error`, `Close() error`.
- Errors: `ErrNotFound`, `ErrConflict` (name taken), `ErrVersion` (version mismatch).
- Cursors are base64 of the sort key and ID. Lists are newest first.
